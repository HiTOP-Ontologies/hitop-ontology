    References¶

    A maintained structure for recording bibliographic sources and per-concept attribution for HiTOP labels and definitions.

    Applies to · Version 0.1.0 · ontology/hitop.rdf

    1. Purpose¶

    Each concept class in ontology/hitop.rdf has an rdfs:label, a definition (obo:iaoIAO_0000115 or rdfs:comment), and optionally a skos:changeNote. This document defines how the corresponding literature source and attribution review are recorded consistently for every core HiTOP concept.

    2. Scope¶

    This document covers:

    • Literature sources for concept labels and definitions in the core ontology (Superspectrum, Spectrum, Subfactor, Component, and Trait).

    This document does not cover:

    • Mapping evidence for manifestation suffixes. That belongs in the maintained mapping and harmonization specification.
    • Provenance for an individual factorization, such as the source of a concrete hierarchy. That belongs in its factorizations/<factorization-id>/v<N>/README.md.

    3. Structure: two linked parts¶

    The document consists of two linked tables:

    • Part A lists every cited source exactly once with a stable short key (citation_key).
    • Part B assigns one or more citation_key values from Part A to each HiTOP code.

    A source is never written out in full in Part B; only its key is used there. This prevents the same source from being cited in slightly different forms.

    4. Part A — Bibliography¶

    Field Required Meaning
    citation_key Yes Stable lowercase key in the form <first-author><year>, for example kotov2017; append a, b, and so on for multiple sources by the same author in the same year
    Full reference Yes Complete Vancouver-style reference (authors, title, journal, year, volume, pages), matching the target Journal of Biomedical Semantics format
    DOI/URL When available Persistent link; use a stable URL if no DOI exists, or - if neither exists; do not leave the field blank
    Coverage Yes One sentence describing what the source covers, such as the complete model or an update to the Internalizing spectrum

    The initial row is intentionally neutral. Replace each placeholder only with verified bibliographic information:

    citation_key Full reference DOI/URL Coverage
    - - - -

    5. Part B — Source attribution by concept¶

    Field Required Meaning
    HiTOP code Yes hitop_base_code from ontology/hitop.rdf, for example S0013h
    Label Yes Current class rdfs:label, included for quick comparison without opening the RDF file
    citation_key(s) Yes One or more comma-separated keys from Part A; at least one is required unless status: pending
    Section/page No Optional section, table, or page in the source where the concept is defined
    Note No For example, a label adapted from the source or a paraphrased definition
    status Yes One of reviewed, draft, pending, or excluded; an excluded structural concept requires a reason in Note
    reviewed by When status: reviewed Name or initials of the person who verified the attribution
    Date When status: reviewed Review date in YYYY-MM-DD format

    The table mirrors the classes in ontology/hitop.rdf; HiTOP code and Label are copied from that source. Structural schema classes may use status: excluded with a reason because they are not domain-specific HiTOP concepts. Use status: pending until an attribution has been verified, and regenerate the table whenever classes are added to or removed from the ontology.

    6. Rules for new entries¶

    1. Every row in Part B MUST describe exactly one HiTOP code, and every code in the canonical ontology MUST have exactly one row, including while its status is pending.
    2. A citation_key MUST be created in Part A before it is used in Part B.
    3. Rows are never deleted without explanation. When attribution changes, update Note and status; Git history preserves the review trail.
    4. When a concept combines multiple sources, all relevant citation_key values MUST be recorded, not only the latest one.
    5. If no appropriate external source exists for a structural helper concept, set status: excluded and record the reason in Note.
